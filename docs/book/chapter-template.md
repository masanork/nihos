# 章の雛形

これは著者向けの雛形で、書籍のentryには含めません。実装があり、実験を確かめられる章から追加します。

## 読者に約束すること

この章で読者が説明・変更・測定できることを二、三点に絞ります。必要な前提知識、実習版のコミット、toolchain、機材、所要時間を記します。所要時間は読者に試してもらってから記載します。

## 観察できる問い

何が起きていて、なぜ調べたいのかを、具体的な操作や失敗から始めます。実行前の予想を促します。

## 仕組みと守る条件

一般的なOS原理を説明し、資源の所有者、状態遷移、呼出し側の責任を明示します。RISC-V、ESP32-P4、Tab5のどこに属する制約かを分けます。

## 最小限の実装

議論に必要な関数・型だけを実ソースから抜粋します。ファイルの全行解説を避け、実行経路と失敗経路を追います。設計理由はADR、測定条件はmeasurementsへつなぎます。

## 実験と観察

コマンド、入力、期待される状態、失敗時の調査先を書きます。host、RV32コンパイル、ESP-EMU、ESP-IDF-hostedな実機、nativeな実機を区別します。過去の測定を、今回実施した結果として記述しません。

## 条件を一つ変える演習

容量、負荷、タイミングなどの一条件を変更します。何を予想し、何を記録し、どの説明ができれば学べたと判断するかを示します。未実装機能を使う演習は本文へ入れません。

## 設計の選択と次の拡張

代案の費用と、別の方式を選ぶ条件を述べます。小さな拡張、再現報告、ドキュメント修正など、読者がプロジェクトに参加できる単位で終えます。
