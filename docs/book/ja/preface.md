# はじめに

小さなOSなら、CPUという回路がプログラムの命令を実行するところから、画面に文字が現れるところまで、自分で追えるだろうか。私はnihosを作りながら、そのつながりを確かめている。本書はM5Stack Tab5を実験機に、OSの仕組みと設計を選ぶ理由を学ぶ本である。

作り始めたきっかけは、MeOSを見て面白いと思ったことだった。手を入れて拡張するうちに、せっかくなら自分の好きな設計で一から作ってみたくなった。M5Stackで動くさまざまなOSや、FreeRTOSの複数コア対応も、作り始めてから知った。本書には、そのような発見と、実験を通して考え直したことも残したい。

画面のデータを誰が書き換えてよいか。機器から処理を求められたとき、何を中断してよいか。別のCPUへ渡した仕事を途中で止めたら、誰が片づけるか。守る条件をコードと実験で確かめることが、システムを作る仕事になる。

本書は、端末で起きる一つの操作を入口に、仕組みを六つのまとまりで追う。章番号は通し番号である。

| 読み進める順 | 問い | 対応する章 |
| --- | --- | --- |
| 端末と機械 | 何を作り、CPUや機器はどう仕事を分けるか | 序章から{{ch:first-experiment}} |
| OSの土台 | 実行、メモリ、入出力の寿命を誰が管理するか | {{ch:native-entry}}から{{ch:io-lifetime}} |
| 画面に表す | 画像や文字から、どう画素と画面を作るか | {{ch:drawing-text}}から{{ch:japanese-fonts}} |
| 読む・書く・道具を育てる | 文書を編集し、自分の操作をどう定義するか | {{ch:editing-environment}}と{{ch:live-editing}} |
| 機器と保存 | 独立した相手や媒体とどう仕事を続けるか | {{ch:networking}}から{{ch:sqlite-persistence}} |
| 統合と発展 | 複数の仕組みを一つの操作につなぐには何が要るか | {{ch:card-terminal}}以降 |

各章の実験は、同じ版で全部が動いたことを意味しない。原理を説明した後に候補、検査方法、観測できた範囲を記す。各版と実習環境は巻末へまとめた。

読者にはCなどで関数、ポインタ、構造体を使った経験を想定する。OSの実装やTab5、組込み機器の知識は前提にせず、必要な機械の仕組みを第1章から順に紹介する。Zigの記法は登場したところで説明する。結果を予想してからコードを読み、手元の実験と比べてほしい。

実習はPC上のテストと生成コードの検査が中心で、Tab5がなくても取り組める。追加のエミュレータ実験と実機の観測も読み合わせる。必要な版と環境は、巻末の[実習環境](practice-notes.md)にまとめた。
