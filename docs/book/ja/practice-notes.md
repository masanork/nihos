# 付録　実習環境

## 実習の進め方

本文の実習は、PC上のテストとELFの検査を中心に構成した。Zigは0.17.0を使い、リポジトリのbootstrapスクリプトで版を揃える。Python 3を使う手順もある。スケジューラのモデル検査にはJavaが必要で、掲載した実験はJava 21で確認した。

ESP-EMUで実行する追加実験には、ESP-IDF v5.4.4とESP-EMU v0.50.0を用いる。エミュレータ上の時刻や動作は、実機の遅延や電気的な特性の測定には用いない。Tab5への書き込みは本書の実習には含めていない。

実習を始めるときは、ソースのコミット、作業中の変更、ツールの版を記録する。性能を測る場合は、入力、最適化、試行回数、時間の単位も揃える。出力先を分け、比較したい結果を上書きせずに残しておこう。

## 後半の実験で変えるもの

通信の実習は模擬応答と模擬時刻を使う。Wi-Fiの資格情報、AP、BLE機器は不要で、RTCのテストも本体の時計を書き換えない。カードの実習も架空の値と模擬transportを使い、実カードへの認証やデータの取得は行わない。

保存と部分更新の必須実習は、RAM上の媒体モデルで実行する。実装ファイルを読む際は、8個のobjectを扱う`cow_model.zig`と、後続のページ化indexを持つ`checkpoint_model.zig`を区別する。同じ関数名でも、型、引数、媒体形式が同一とは限らない。

file runnerは、新しいホストファイルと自分で起動した子processを使う。16 GiBの疎fileを扱うrunnerもある。論理容量と実際のdisk使用量は異なり、疎領域を維持せずコピーすると使用量が増える。SQLite保存章の必須実習もこの方式を使い、実SDへは接続しない。SIGKILLによるprocess終了、媒体モデルのcache喪失、実機の電源断を区別する。

SQLiteのcache比較は追加実験で、300箇所のmalloc／realloc失敗と正常な再openを多数の子processで検査する。小さいPERSIST回復試験と同じ参照版を使うが、別のrunnerと出力directoryで結果を保存する。

日本語フォントの必須実習にはCMake、C++17 compiler、Python 3、curlとZigを使う。固定版のFreeType、HarfBuzz、fontを取得し、検査した上でローカルpatchを適用する。C/C++のsanitizerと、Zig側のReleaseSafeは異なる検査である。既定のhost試験は二つのsession、確保失敗、kernel backingを扱い、RV32のstack比較は追加のtoolchainと命令実行環境を使う。

FatFsのrunnerにもC/C++ compilerが必要で、同じ版のprobe資料に従いRV32 compilerを用意する。6 GiBの疎なexFAT imageも生成し、前後のhashでは全体を読むため、転送量と処理時間を見込む。IMUと音声の必須実習はZigの模擬bus／clockで動き、設定uploadや出力を実機へ送らない。

## 実機の観測との対応

後半で読む実機記録は、表の各参照版に収録された、その試験の候補と設定に対応する。表の先端の全機能を一つのイメージで同時実行した結果ではない。

| 記録 | そこで確認したこと | 別の条件として残るもの |
| --- | --- | --- |
| 通信の更新と復旧 | 早めた更新ACK、C6 reset後の再取得 | 自然なT1/T2、長時間、全体の電源断 |
| BLEとboard I2C | 広告探索と停止、RTC等のregister読取り | GATT/HID、RTC設定・保持、IMU sampling |
| SDの寿命 | 取消通知、実抜去と再挿入、停止と返却 | 書込み中断、物理DMA途中の抜去の測定 |
| ストア | ホストの中断モデルとfile再open | native接続、実SD書込み・電源断、永続SQL |
| カード表示 | 特定候補での四情報・写真・消去 | 後続自動reader・免許証の実機と署名確認 |
| IMU | 設定全量と六軸の連続取得 | 制御した運動、校正、FIFO/IRQ、画面の軸対応 |
| 音声 | 有限PCMのDMA、clock/FIFO、停止・返却 | 可聴確認、アナログ測定、連続再生、録音 |
| Canvas fixture | 静的pattern、表示開始、割込み進行 | 光学確認、実pixel、tearing、実アプリの時間 |
| 音声wire追加試験 | 観測区間のI2S wordとPCM計画の一致 | codec以降、可聴成功、Quake音声 |

永続SQLite、FatFsの新しい接続、日本語フォントのbackingはホストで検査した事例である。日本語フォントのRV32実行も、独立した命令実行fixtureであり、native OSのtaskや実機の表示結果へ読み替えない。付録の古いストア行と、新しいSQLite行も、それぞれの章に対応する版として残す。

## カバレッジを収集する追加実験

まず本文の固定済み報告を読む。自分で収集する場合は`980f522`の作業用コピーで、[metricsの手順](git:980f522a3575c3922b956bf97f46a228b557070d:metrics/README.md)に従う。Linux、kcov v43のビルド依存、ZigのLLVMコード生成を使う。Linuxコンテナでは実行追跡の許可も必要になり、macOS上の通常のホストテストだけでは同じ収集を行わない。

収集は`python3 tools/host_coverage.py --kcov <kcovの実体パス>`で行い、`build/metrics/host-coverage.json`と生のHTML/XMLを読む。報告のハッシュとソースが一致すること、対象のテスト入口、コンパイラとホストの構成、報告に現れないファイルも確認する。集計やグラフを見るだけなら、kcovを使わず`python3 tools/metrics.py`でソース量を測れる。行数と実行カバレッジは別の測定である。

## 実機候補を識別し、元の状態へ戻す

本書の必須実習は実機へ書き込まない。実機測定の記録を読む際には、「動いた」という一行に加え、機体、ソース、設定、実際のイメージ、開始前後の照合、復元結果が同じ試験へ結び付いているかを見る。

カメラの[露出比較での中断記録](git:980f522a3575c3922b956bf97f46a228b557070d:docs/measurements/2026-10-30-camera-low-exposure-incident.md)では、標本とフレームバッファが一致した後、候補の事後検証中にUSB接続が消えた。自動復元も失敗したため、バックアップと失敗記録を保持し、失敗後に自動リセットを行わなかった。再接続後、同じ機体と書込み所有権を確認し、バックアップを書き戻して全範囲の読戻しを照合した。

後から元のイメージを復元できたことは、途切れた試行の事後候補検証が成功した意味にはならない。復元後の起動ログも、その記録では取得していない。撮影、候補の照合、復元、復元後の起動を別々の結果として残すと、次の実験が何から始まるかを判断できる。

また、USBリセットでは、周辺回路の状態が常に同じように初期化されるとは限らなかった。[リセット回復の実験](git:980f522a3575c3922b956bf97f46a228b557070d:docs/measurements/2026-10-30-camera-reset-recovery.md)は、準備済みCSIを保持する明示的な試験から全チップリセットへ進む経路を確認した。自然に残った状態からの自動早期起動経路、冷電源投入、DMA動作中の中止まで実証したものではない。リセット方針には、再起動を繰り返すループへ入らない条件も必要になる。

連続撮影の最終試行では、候補の事前・事後照合、元のFlash範囲の復元、全読戻しを記録した。複数人や複数の作業用コピーが同じ基板を使う場合、シリアル接続だけでなく書込みの所有者も一つにする。別の作業が書いたイメージを測ったり、相手の保存領域を復元で上書きしたりすれば、ログの内容だけでは実験を識別できなくなる。

## 本書で用いる言葉

機械の基本用語は{{ch:machine-basics}}で、バイトと番地、CPUの実行状態、メモリマップ、割込み、DMA、キャッシュの順に導入する。ここは実習へ戻るための補足であり、巻末の用語集を先に読むことを前提にはしない。

PC上でデータ構造や方針を試す実行をホストテストと呼ぶ。ネイティブ実行は、ESP-IDFのアプリケーション初期化やFreeRTOSのタスク管理を通さず、nihosが実行状態を管理する経路を指す。ROMと第2段ブートローダは利用する。ESP-IDF上の実験、ネイティブ実行、エミュレータと実機を区別して読むための呼び名である。

アリーナは一つの領域から順にメモリを切り出す割当方式、ヒープは個別の確保・解放を扱う領域として用いる。所有者は、ある資源の状態変更と回収を担当するCPUやタスクを指す。型やAPIで所有者を決めることと、ハードウェアで他者のアクセスを防ぐことは区別する。
