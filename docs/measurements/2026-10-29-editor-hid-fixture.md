# Tab5 HID input through the editor redraw fixture

The finite `console-rv32` edit scenario now feeds a synthetic FIFO through the actual Tab5 keyboard driver's `begin` and bounded `poll` methods, using a deterministic I2C register model with keyboard mode already set. The driver filters one release and one malformed usage. The fixture adapter uses the existing shell HID decoder for printable ASCII, Shift, Caps Lock and backspace; it maps unmodified left/right usages to cursor movement and ignores modified arrows and non-editing controls. The trace includes a rejected Ctrl-C, a rejected Shift-right, six editing actions and driver count assertions. No physical bus, keyboard or mode write is exercised.

The edits and partial redraw occur after scrolling. At commit `7333b123e9fc29aad27f7857bcfc0a1ae408aa90`, ESP-EMU ran the complete driver → decoder → bounded row edit → console renderer path. The final frame matched both the host fixture and an independently specified per-pixel reference for [basic-light](evidence/2026-10-29-editor-hid-fixture/basic-light.json), [JetBrains](evidence/2026-10-29-editor-hid-fixture/jetbrains.json) and [Source Code](evidence/2026-10-29-editor-hid-fixture/source-code.json). These hashes match the prior direct-action fixture, and frame guards passed. Host tests cover decoder modifiers, Caps Lock, FIFO batching, release/malformed filtering and per-edit incremental-versus-full repaint.

Run `sh tools/nihos-dev.sh console-rv32 --font basic-light` and repeat with `jetbrains` and `source-code`. This is a fixed synthetic input and final-frame test, not interactive browser key injection, a full XY editor, Unicode/IME, storage, a physical I2C test or a performance measurement.
