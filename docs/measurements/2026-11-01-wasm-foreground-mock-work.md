# Bounded foreground work during Wasm sessions

The headless repeat fixture now performs two deterministic pieces of work on
each observed foreground turn: hash 64 generated bytes and sum 16 generated
10-bit samples. The UART runner independently recomputes both results in Python
and checks every per-round count and aggregate. This is synthetic CPU work; it
is not an implementation or simulation of a camera, packet protocol, network,
storage device, DMA or their drivers.

In one RV32 emulator boot, the runner executes the same three rounds: an active
session, an opening cancellation, and another active session. For active
sessions it sends `0 → 1 → 0`, waits until at least five active-phase foreground
turns have occurred, then quits. The presenter checks every logical pixel and
frame order; each round also checks shell return and memory/task recovery.

| Round | Scenario | Opening turns | Cancellation turns | Active turns | Work items | Maximum observed gap |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 1 | active then quit | 109 | 0 | 7 | 116 | 20,055 us |
| 2 | immediate open cancellation | 1 | 110 | 0 | 111 | 20,003 us |
| 3 | active then quit | 109 | 0 | 7 | 116 | 20,003 us |

Each work item consists of both operations above; counts match the sum of the
three phase counts. Digests and sample sums match the independent reference.
The maximum is measured in emulator time between foreground probe turns or to
the return of UI service. It is an observation for this one workload and input
sequence, not a physical latency or a worst-case bound. The runner retains its
200 ms test-only regression ceiling. Rendering and active-session close remain
synchronous: synthetic work can run between UI calls, not while one is blocked.

Debug and ReleaseSafe tests, static analysis, 501 Python regressions, the
previous UART cases, three native-session cases and six existing Wasm session
cases were rerun. See
the [evidence record](evidence/2026-11-01-wasm-foreground-mock-work/identity.json)
and [reproducible runner](../../probes/wamr-native/run-repeat-emulator.sh).
Actual device services, physical scanout/cache behavior, USB input, WAMR
alignment and Tab5 qualification remain open.
