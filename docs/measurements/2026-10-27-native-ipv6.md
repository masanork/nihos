# Native IPv6: physical link-local qualification

2026-10-27. **Physical DAD, NDP and IPv6 Echo responder pass** on Tab5 using
existing C6 Hosted 1.4.1. SLAAC and outgoing router Echo are host-tested only:
the current AP returned no RA during 3 RS messages / 15 seconds of discovery.
This is a bounded boot fixture, not the normal OS network service.

## Implementation and verification

`src/net/ipv6.zig`: MAC-derived EUI-64 link-local, one DAD probe and one-second
wait, solicited-node MLDv2 report with Router Alert, RS/RA, one autonomous /64
prefix and DAD, one router/neighbor resolution, nonce-matched Echo reply and
an incoming NS/Echo responder. Malformed checksums/hop limits/options, zero-length
options, truncation, duplicates and mismatched Echo payloads are rejected.

`NIHOS_C6_PROTOCOL=hosted NIHOS_C6_IPV6=1` builds private
`build/c6-ipv6-probe/`, with the existing `NIHOS_C6_WIFI_CONFIG` JSON option.
Generated modules and images contain credentials and must stay local.
C6 firmware is unchanged; P4 factory app only was written. Full-flash backup
was skipped per the user's explicit instruction.

- Debug / ReleaseSafe: 162/162 each, including IPv4 regressions.
- Independent Scapy 2.6.1 RA/NA/MLDv2/DAD fixtures. MLD and DAD TX match exactly.
- Tests cover DAD states, malformed packets, no router, NA resolution, incoming
  and outgoing Echo, plus dual-stack and IPv6-only orchestration.
- Format/ZLint/shellcheck, RV32 codegen, 6 native ELF audits and 5 image tests pass.

Protocol references: [RFC 4861](https://www.rfc-editor.org/rfc/rfc4861),
[4862](https://www.rfc-editor.org/rfc/rfc4862),
[4443](https://www.rfc-editor.org/rfc/rfc4443),
[3590](https://www.rfc-editor.org/rfc/rfc3590),
[3810](https://www.rfc-editor.org/rfc/rfc3810). No MeOS source was copied.

The final Mac test waited for `NIHOS_C6_IPV6_LINK_READY`. Earlier attempts
started during initialization and received 1/5 and 3/5 replies; those logs are
retained and are not steady-state loss measurements. This is one short warm-reset
test, not long-running loss/latency or cold power-cycle qualification.

The Mac on the same AP also had no active en0 IPv6 default route and only
deprecated cached global addresses. That is consistent with the lack of RA,
not proof that the AP can never provide IPv6. No router settings were changed
and no RA was injected. Global IPv6 connectivity is unqualified.

## Limits

No sockets, DNS, DHCPv6, full MLD listener, NUD cache, fragmentation, privacy IID,
complete prefix-lifetime updates or normal OS integration. Only initial address
acquisition is modeled; EUI-64 exposes the station MAC. The fixture halts after
recording results. Physical SLAAC/router Echo needs an IPv6-advertising network.
