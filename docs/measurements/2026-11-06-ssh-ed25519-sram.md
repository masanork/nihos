# SSH Ed25519 table and SRAM placement study

This is an offline link study on integration candidate `1da537d999e6c2a3dcac99c1d962e7a15e749c79`, not a bootable or qualified native SSH build. The study forced the existing always-unavailable entropy stub through the foreground link path; it did not supply credentials or working entropy. Study images were not run or flashed. The production SRAM region and 49,152-byte heap assertion were not changed.

The unmodified product-size link overflowed SRAM. A separate diagnostic link temporarily modeled 320 KiB of RAM to identify retained symbols. In that diagnostic only, moving the prepared-foreground poll, SHA-256 and SHA-512 rounds and scalar reduction into mapped Flash still left only 2,368 bytes before the real 160 KiB boundary. A broader exploratory `.text.ssh*`, `.text.vt100*`, `.text.crypto*` placement linked under the real boundary with 49,856 bytes of heap, but the standard image audit correctly rejected its unapproved Flash functions. Its 704-byte margin, unreviewed interrupt/cache-off reachability and lack of a qualified entropy owner make this an analysis artifact, not a proposed placement policy.

A 2,688-byte Ed25519 precomputed base-point table remained in SRAM at `0x4ff15bf0` in that broad link. Its SHA-256 `97dfc18d19f9cf8952f9409cffe06bba8804cfdc21a731ff9705dc887e49f75b` matches the named Flash-resident table in the existing P4 PQC emulator fixture. The linked symbol is anonymous (`__anon_84718`) and the pinned Zig compiler emits it inside a shared `.rodata` input section; a linker selector for `.rodata.__anon_84718` did not move it. Moving the entire shared section without proving every cache-off and IRQ consumer is not justified.

`python3 tools/audit-ssh-ed25519-table.py ELF --require-flash` locates the pinned table by its content and checks that the entire table has exactly one read-only mapped-Flash copy and no full copy in allocated SRAM. It is a focused placement check, not the native image audit or proof that code execution is safe. The check passed against the retained PQC fixture and rejected both the SRAM-resident study ELF and an ELF deliberately modified to contain an additional SRAM copy. The normal SSH-disabled device image has no such table. Source/compiler changes can change the table; a missing matching symbol fails closed with `--require-flash`.

## Isolating the table with data sections

The link-only fixture `probes/ssh-placement/run-link-study.sh` adds Zig's `-fdata-sections` in a disposable worktree, making this pinned compiler's anonymous table a separate `.rodata.__anon_84718` input section. The fixture selects that exact input for mapped Flash and checks the content hash, placement and absence of a full SRAM copy. At source `341d6f0c03e149bdf344afa2925cea92885e4d81` the retained summary reports **54,080 bytes** of heap and exactly one read-only Flash table. The normal native audit still rejected unapproved SSH/crypto code placement. The fixture requires that rejection and deletes its temporary worktree and generated images; only its report and build log are retained.

The anonymous name depends on compiler and source details; a changed name or table causes the positive check to fail. This is a reproducible direction for a future guarded placement, not a production linker rule or authorization to execute the broad Flash code. In particular, the fixture uses the always-unavailable entropy stub, has no network session, and does not prove interrupt/cache-off reachability, device behavior or physical entropy.
