# CSI receiver preflight on the current integration base (2026-10-30)

Base `d824feaa8acc66dc16810fc9fa95887f5efc642d` plus the uncommitted camera integration worktree. The explicit default-off camera diagnostic fixture accepts `:csi-probe` only while the sensor diagnostic is idle or finished; a running or pinned CSI probe blocks sensor requests. CSI preparation checks the MIPI regulator enable bit and rejects pre-existing CSI clock ownership before touching the receiver. It configures the CSI host/bridge for one lane and 1280×720, verifies selected registers, and stops the receiver and checks the relevant clocks are off. It does not start sensor streaming, bridge output, ISP or DMA. A partially touched receiver requires cleanup and an unconfirmed stop pins the probe.

One physical Tab5 ESP32-P4 rev 1.3 trial, MAC `e8:f6:0a:e2:e8:9c`: app SHA-256 `aefc8fb544eef32b8b98ad55e71b33a0ec94d06c62bac5377ebd0c5eed10a79f`, ELF SHA-256 `9ea19697186df83b649fe12495629002881686030446497a7116adcfa7b65c35`. [Receipt and image audit](evidence/2026-10-30-csi-preflight-main/). After two idle reports, request kind 8 was accepted; two repeated terminal reports recorded state 3/result 1, meaning receiver preparation and stop/readback succeeded. Launcher readiness and display frame and CPU counter progress were recorded. The register report is one trial, not a PHY signal or image proof.

Host state-machine tests and a register replay using the pinned ESP-IDF 5.4.4 LL structures cover admission rejection, unrelated display clock preservation and cleanup. The replay cannot model asynchronous hardware, electrical power or PHY signaling. This diagnostic masks CPU0 interrupts around its shared clock updates; it does not establish safe concurrent RCC modifications by another core or arbitrary peripheral. The fixture ran with network and normal storage disabled; touch, audio and other concurrency are not qualified by this trial. Normal and diagnostic native builds passed image audit. The original loader and app spans (24,576 and 151,552 bytes) were restored and fully read back, then hard-reset; no restored-system boot log was captured. Raw logs remain private.
