# Tab5で開くxyのホームとオフライン本棚

Mac版のホーム・本棚に続き、Tab5の通常起動をホームへ接続した。
内蔵Flashの本とフォントを使い、タッチで本・章を開き、本文を読める。
実機に導入し、シリアル入力での検証後、利用者から
**「本文が見え、タッチでも本が開ける」**との確認を得た。

実装ブランチは `codex/xy-tab5-reader`、親はMac版の `d44186b`。
元の作業ツリーにあった4ファイルの変更とMac版の作業ツリーを保持した。
証跡は [evidence/2026-10-31-xy-tab5-reader/](evidence/2026-10-31-xy-tab5-reader/)。

## 使い方

起動後のホームには、文書、使い方、草枕、SICP、端末の書籍、表示設定の6項目がある。
本をタッチし、目次から章を選ぶ。本文下部にはホーム、前へ、次へ、目次、設定を置いた。
本文の左右をタッチしてもページを送れる。目次は8項目ずつ表示し、下部で一覧を送れる。

| キー | 操作 |
| --- | --- |
| ホームで `1`–`4` | 使い方、草枕、SICP、端末の書籍の目次 |
| 矢印・Enter | ホーム・章の選択、読書中のページ送り |
| Space / `n`、`p` | 次のページ、前のページ |
| 読書中に `c`、`s`、`i` | 目次、表示設定、著者・利用条件・出典 |
| Esc / 読書中の `h` | ホームへ戻る |
| ホームで `r` | 読んでいた章・ページへ戻る |
| 設定で上下 / `+`・`-` | 本文16–64px、4px単位 |
| 設定で左右 / `v`、`f`、`t` | 縦横、明朝・ゴシック、明暗の切替 |
| 設定でEnter | 設定を反映して戻る |
| ホームで `n` | RAM上の文書を書く・再開する |
| 文書でCtrl-C | 文書を保持してホームへ戻る |

初期値は32px・明朝・横書き。設定変更時は、現在のページ先頭のUTF-8位置から組み直す。
今回の実機確認後は、草枕の32px・明朝・縦書き・明るい紙面を開いた状態にした。
その後の利用者のタッチ操作による画面変更は妨げない。

## 収録内容と実装の境界

| 本棚 | 収録内容 |
| --- | --- |
| xyを使ってみる | Tab5向けの操作、表示設定、RAM文書とSchemeの3項目 |
| 夏目漱石『草枕』 | 青空文庫版全13章、ルビ付き |
| SICP | 英語Scheme版の1.1、1.1.1、1.2.1の3節 |
| 『小さなOSを育てる』 | 本リポジトリの書籍32項目、本文・コード・図の説明 |

51項目と日本語フォント2書体を、2,894,774 bytesの読取専用パックへ変換して
Flashに同梱する。SDカード、開発用フォント、ネット接続を必要としない。
本文、ルビ、出典はMac版と同じ `assets/xy/library.json` から生成する。
使い方の本文だけ、Tab5で利用できる操作に置き換える。
原典・ライセンスは [Mac版の記録](2026-10-31-xy-home-reader.md#収録内容と出典)、
`provenance.toml` と `third_party/xy-reading/` を参照。
SICPは全巻・日本語訳ではない。フォントは既存のCC0サブセットを再利用する。

本の本文を編集用バッファに置き換えず、文書はUndoやルビとともに保持する。
読書画面からの編集・Scheme編集コマンドを拒否する。
設定、読書位置、文書はRAM上に保持し、再起動後の永続化は未接続。
Tab5の文書作成はRAM文書であり、Mac版のファイルを開く・保存するダイアログはない。
書籍の図版は説明文で読み、Tab5でSVG図を開く機能は含まない。
戻るページ履歴は最大256件で、履歴のない前章への移動はその章の先頭になる。

## ネイティブ描画とメモリ

Flashパックはオフセットと長さを検査して参照する。実行時のJSON解析や全巻のRAM展開はしない。
ページ候補は400クラスタ・約3000 UTF-8 bytes、ルビ64組・1024 bytesまでとし、
共有の組版・ルビ境界・実際の配置によるページ末尾判定を使う。
描画リストを512 glyphへ拡大し、1024版はnative監査の許可対象にしない。
物理720×1280のRGB565画面に、論理1280×720の本文と72pxの操作領域を描く。
タッチ座標は既存ポインターサービスが変換済みの論理座標を一度だけ使う。

SliceReaderが保持するスライス記述子をSession内に所有し、呼び出し元の一時変数への
参照を残さない。描画用PSRAMにはSession、完成フレーム、ガード付きスタックを確保する。
Flashの読取専用領域を拡張する一方、実行可能領域と書込可能領域の監査制約は保持する。
4MiB factoryパーティションを読書用ビルドに選択する。

| 値 | 実機導入したtrace版 | 最終通常ビルド |
| --- | ---: | ---: |
| イメージ本体 | 3,499,168 bytes | 3,498,224 bytes |
| primary SRAM heap | 49,216 bytes | 49,344 bytes |
| 監査のheap下限 | 49,152 bytes | 49,152 bytes |
| 読書描画スタック確保 | 262,144 bytes | 262,144 bytes |
| xy Flashコード | 61,104 bytes | 60,448 bytes |
| xy Flash読取専用データ | 2,942,132 bytes | 2,942,132 bytes |

最初の実機候補は128KiBの描画スタックで、草枕を開く際に
`NIHOS_NATIVE_FAIL interrupt stack/MIE` を検出した。
変更した全セクタを元に戻し、元の16MiB Flash全体とのdigest一致を確認した。
次の候補では確保量を256KiBに揃え、ガードを維持したまま再検証した。
全29観測のスタック最大使用量は142,352 bytes、最後の新規起動では142,208 bytes。
128KiBでは不足する実測結果であり、ガードを緩めて通過させたものではない。
SRAMの48KiB下限も維持し、既存の不変文字列・キーマップをFlashへ移した。

## 実機の識別・書込み・復元

対象は `/dev/cu.usbmodem101`、ESP32-P4 rev1.3、MAC `e8:f6:0a:e2:e8:9c`。
既存の端末書込みロック、cu/tty両方へのカーネル排他、利用プロセス確認を行った。
候補を私有ディレクトリへ固定し、監査済みELF・イメージhashと照合した。
16MiB全体の私有バックアップを作り、書込み前に実機全体との一致を検証した。

書込みはbootloader `0x2000`、partition table `0x8000`、app `0x10000` と
それらの消去セクタに限定した。インストール後は候補のreadbackに加え、
元Flashへ変更セクタだけを重ねた期待値と16MiB全体を照合した。
NVSを含む変更セクタ外の一致を確認し、SDへは書き込んでいない。
バックアップ・復元用断片・Flash全体の期待値・バイナリは私有のまま保ち、証跡へ同梱しない。

導入したappのSHA-256：

```text
731fa38049e81b2fa718b88c07f3a72bfe50838fe1940a187327a970a164f087
```

通常版のSHA-256は `ec7fc38cb04fc5e70457659949fb6c91930a74ba04bb17ac5ea53160228204b6`。
通常版はビルド・監査までで、実機に残したのは上記trace版。

## 検証と証跡

| 検証段階 | 結果 |
| --- | --- |
| Zig host tests | 最終ソースで73/73 steps、1014/1014 tests成功 |
| Tab5の共有描画・入力結合試験 | 7件成功。全51項目の縦横表示、草枕第一章の連続読了、ルビ・パック一致、タッチ、設定、一覧送り、不正パック拒否 |
| Mac既存結合試験 | 読書8件、ワークスペース16件成功 |
| native image監査試験 | 41件成功。読取専用領域の拡張とRX/RW制限の維持を含む |
| 静的検査 | 変更Zig14ファイルのfmt・ZLint成功、0 errors / 0 warnings。shellcheck・diff検査成功 |
| 実機・自動 | 29観測成功。ホーム、草枕前後ページ、縦横・36px・ゴシック・暗色への変更、SICP、書籍第4項目、文書保持、再起動後のホームと読書 |
| 実機・利用者確認 | 本文の可視表示、物理タッチによる本の選択・表示を確認 |

自動検証では編集文書 `xy note` の7 bytesとFNVを、ホーム往復後も照合した。
草枕の最初のページはUTF-8位置0–697、次ページ697–1530で、前ページへ戻れた。
最後の32px縦書きは0–866を描き、描画失敗0、予期しない再起動なし。
利用者確認後の追加リセットや書込みは行っていない。
実機光学確認は利用者からの確認であり、フレームバッファとの画素単位比較ではない。
冷間電源投入・長時間連続読書・保存・電断復旧の検証は今回に含まない。

`physical-result.json` は自動観測と利用者確認の出所を分けて保持する。
`physical-xy-trace.log.gz` はXY関連の行だけを抽出し、初回失敗と復元照合も別に残す。
`source-files.json` は最終ソースと入力資産のhash、`reading-pack.json` はパックのhash。
`host-home.png` と `host-vertical.png` はホストで同じTab5描画コードを動かした参考画像で、
実機写真ではない。CIのMacジョブにもTab5プレビューのビルドと7試験を追加した。

## 再現

```sh
sh tools/build-xy-tab5-preview.sh
python3 tools/xy_tab5_reader_test.py -v
zig build test --summary all
python3 tools/native_image_test.py -v
sh tools/build-native.sh device
NIHOS_NATIVE_XY_TRACE=1 sh tools/build-native.sh device
```

実機検証用ツールはESP-IDFのesptool・pyserialが入ったPythonで実行する。
出力先は新しい私有ディレクトリを指定する。

```sh
python tools/qualify-xy-reader.py /dev/cu.usbmodem101 \
  build/native-device-network-devices-camera-xy-trace \
  /private/tmp/nihos-xy-reader-new-capture --install
```

このコマンドはファームウェアを書き換える。対象MAC、監査identity、排他、
バックアップ全体の一致を満たしてから書き込み、検証失敗時は変更セクタを復元して
元の16MiBとの一致を検証する。既存バックアップの再利用も、実機全体との一致が条件。
