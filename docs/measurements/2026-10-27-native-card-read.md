# Native Input Support read: device integration checkpoint

2026-10-27 JST、ソース `0a1370c`。Tab5 / ESP32-P4 rev1.3、ST7121、
Sony PaSoRi RC-S300/P 054c:0dc9。

本体の実PIN入力、1回限りのVERIFY、EF0002の基本4情報、
日本語のページ表示、画面終了時の消去を専用DISPLAY=9に結合した。
PINのないテンキーデモについて、ユーザーから「動いてるね」と確認を得てから進めた。
この観測を新しい認証付き読取の成功とは扱わない。

## 書込イメージ

- アプリ：609,216 bytes
- アプリSHA-256：`1eaf29418b0add0b6c6d5e51d873cd6642f2887228d930db2ec6986847eaae25`
- ELF SHA-256：`6267371a88003222b52d906774e85a9a82b1343bff05e3c66a54ecc7f5c7d828`
- 内部SRAMヒープ：50,176 bytes。既存の48 KiB下限を維持。
- 個別許可したforeground Flashコード：25,884 bytes。割込み処理はSRAM。
- 日本語表示用の固定フォント：11,336 glyphs / 408,096 bytes、読取専用・実行不可。

最初の統合リンクはヒープ下限を満たさず不合格にした。
PIN/属性の処理と描画のforeground関数を個別に許可したFlash領域へ移し、
I2Cの同じ実装を共有して収めた。下限やスタックの予約は変更していない。
容量調査用の下限なしELFはbuild内だけの診断物で、Flashへ書き込んでいない。

## 実機で確認した準備

既存300ラウンド、タスク終了、IPI/idle、内部・外部メモリの検証を通過した後、
PINなしで残り回数を確認した。給電制御OFFの読返し、PHY停止前のUSB実切断、
DMA停止・消去も、PIN入力を許可する前の別セッションで確認した。
その後で読取用セッションを新しく開き、残り3回を確認した。

初期画面の表示開始と32フレームのIRQ更新は、エラー0で通過した。
PIN入力開始の記録は `remaining_before=3 / verifies=0 / preflight_cut=1`。
この時点ではPINの送信も属性値の読取もない。

## 検査と残る実機範囲

ホストDebug/ReleaseSafe、Python 136テスト、ZLint 106ファイル警告0、ShellCheck、
既定6構成のRV32 ELF監査、カードAPIのRV32 compile-onlyを通した。
DISPLAY=8も別ディレクトリで再リンクし、Flash資産とSRAM領域を監査した。
密な日本語84文字のページと実PIN画面が専用SRAMに収まること、
プラン再生の画素が実装の描画と一致することをホストで確認した。

実カードのPIN送信、認証応答、基本4情報の読取、日本語表示と消去の成功は、
利用者の本体操作を伴う完了記録と可視確認で判定する。
本モードは発行者署名・証明書チェーンの検証を行わず、結果画面にも明記する。
個人番号EF、顔写真、署名APは対象外。

## 入力待ちの終了と現在の機器

今回の180秒の入力待ちは、PIN送信0回のままタイムアウトし中止した。
完了記録は `status=2 / fault=cancelled / remaining_before=3 / remaining_after=3 /
verifies=0 / cleanup=2 / vbus_off=1 / attributes=0 / shown=0 / erased=1`。
従って認証・属性読取・結果表示は未実行で、成功マーカーは作成していない。
前後Flash照合はbootloader・partition・appの3領域すべて一致した。

最初のログ検査は、専用所有者モードを従来のUSB起動プローブと誤認して不合格にした。
ホスト側検査を、監査済みの専用イメージとPINなし終了準備の記録を要求する形に修正した。
通常のUSBプローブ条件は緩めず、専用所有者の準備は別の証拠として返す。
修正後の独立した表示・メモリ検査は合格したが、認証付き読取の完了検査は
読取結果がないため引き続き不合格である。Python回帰テストは137件となった。

最終Flash照合後にシリアルを解放した。後の接続では別のコンソール用イメージの
ログを観測した（PSRAMを表示元とする横1280×縦720、CONSOLE_STYLE記録）。
この別起動を今回の読取版の記録へ混ぜず、他作業のファームウェアを再度上書きしていない。
接続は解放し、実機の優先作業をユーザーに確認した。現在の機器を読取版と仮定せず、
PINを入力しないよう案内している。

## 利用者の閲覧確認

ユーザーから「閲覧できた。別々に表示せず、まとめて表示できた方がいいんじゃないかな。顔写真も含めて」
との報告を得た。4情報を閲覧できた可視の確認として保持する。保存済みattempt-2の
キャプチャはPIN送信0回の入力待ち中止で終わっており、その後の閲覧実行の
認証応答・終了時の消去までを同じログで確認した記録ではない。キャプチャの判定は変えない。
この閲覧確認だけを取り直すための追加PIN送信は行わず、次の一画面・顔写真の実装へ進む。
