# Ed25519 package verification on RV32 emulator

Date: 2026-10-29. Experimental worktree based on
`c0ff17d5ea6802eed4769a5b588da1735dbfbd32`. This is compile and emulator
evidence for an experimental signed-package load path, not physical Tab5
timing, production key provisioning, or a production installer/loader.

## Compile boundary

`probes/wamr-native/ed25519-rv32.zig` exports the strict verifier through a C
ABI and compiles for soft-float RV32IMAC/ILP32. Its standalone relocatable
object contains 67,548 bytes of text, 3,769 bytes of constants, and unresolved
`memcpy`, `memset`, and `__lshrdi3` references. The integrated image resolves
all three through the existing nihos compatibility/compiler-runtime boundary
and has zero undefined symbols. The object advertises RV32IMAC plus Zicsr and
Zifencei, with no floating-point ABI.

Zig `build-obj` does not expose the C frontend's stack-size-section option, so
static frame metadata is not claimed. The emulator instead uses the existing
64 KiB canary-painted private WAMR stack.

## Executable result

The build creates a deterministic 1,419-byte `NIHPKG01` package from the exact
1,211-byte Rust Wasm using public RFC 8032 test material. A host builder installs
it into an 8,480-byte two-slot package journal and installs a root-signed trust
snapshot into a 1,216-byte trust journal. A second deterministic package carries
sequence 2. The journals, 8-byte counter fixture, 32-byte root and update
candidate are embedded read-only in the second mapped Flash span. Before
WAMR initialization, CPU0:

1. authenticates and seals trust epoch 1 from the trust journal;
2. reconstructs trusted-key, revocation and rollback state;
3. recovers sequence 1 and strictly verifies Ed25519;
4. injects `PowerLoss` at the sequence-2 commit-record write after two syncs;
5. replaces the coordinator and recovers sequence 1 from the partial medium;
6. retries sequence 2 and commits it with three syncs;
7. replaces the coordinator again and recovers sequence 2;
8. recomputes the Wasm digest and applies SDK/service/resource policy;
9. rejects a one-byte-truncated recovered package as a negative control;
10. copies only the authenticated payload into two mutable WAMR buffers;
11. records a 32-bit `cycle` CSR delta and private-stack canary high-water.

Two complete rebuild-and-emulator runs produced the same record:

```text
NIHOS_NATIVE_PACKAGE signature_status=00000001 boot_admission_cycles=065d5815 boot_admission_stack_used=00005c4c package_trust=00000000 initial_sequence_low=00000001 initial_sequence_high=00000000 interrupted_update_recovered=00000001 installed_sequence_low=00000002 installed_sequence_high=00000000 package_sequence_low=00000002 package_sequence_high=00000000 package_syncs=00000003 simulated_reboot=00000001 package_rejected=00000001 boot_recovered=00000001 trust_epoch_low=00000001 trust_epoch_high=00000000
```

That is 106,780,693 emulator cycles and 23,628 bytes of observed private stack
for the complete root/trust/package interruption, install and restart-recovery
closure, not signature-only cost. Each restart is a fresh coordinator in the
same process, not emulator restart or power-cycle evidence.
The timer group is intentionally not enabled at this boot stage, so cycles are
reported instead of fabricated microseconds. Neither number is a physical
latency/stack claim.

The integrated mapped-Flash span contains 249,072 text bytes and 35,147
read-only bytes including the journal/counter/root fixtures. The normal 160 KiB
primary SRAM does not hold the verifier or coordinator code/constants. WAMR's
two lifecycle/recovery checks, three SMP markers, 300-round soak, and final
integer marker still pass.

persistence, protected counter behavior, real install/update interruption and physical
qualification remain separate later gates.
