# Native UART1/RS485 foundation: internal controller checkpoint

2026-10-28 JST, based on main `2cb9143` after merging microphone PR #11.
This checkpoint covers internal UART loopback and its timeout control. **The
external SIT3088 transceiver, A/B wiring and peer exchange are unqualified.**
See [ADR 0051](../adr/0051-native-rs485-bounded-exchange.md).

## Physical controller comparison

Each candidate requested one finite 64-byte exchange ten seconds after normal
boot. Both internal modes held physical DIR34 low throughout and left UART TX
unmapped from GPIO20. Polling transferred at most eight FIFO bytes per call.
The success path waited for FIFO empty **and** transmit-FSM idle before moving
from logical transmit to receive. No UART IRQ, DMA or application IPC was used.

The loopback-disabled image receives constant-high UART RX through the SDK's
GPIO-matrix route. Its timeout is intentional feature failure, not a native
kernel failure. The negative checker requires full TX, zero RX, fault 4 and
successful cleanup; generic failure cannot substitute. These two distinct image
identities are never relabeled as repeated runs of one candidate.

Nominal 115200 8N1 is programmed from XTAL40M / (347+3/16). Internal TX and RX
share the clock; this test does not measure baud accuracy or external wire
compatibility. Neither internal mode exercises a physical DIR high-to-low
transition or differential A/B drive. Wi-Fi was unconfigured, so active AP
traffic remains unqualified. Display/core checks prove controller progress,
not visible display or input confirmation.

## Failure exposed and corrected

The first candidate refused to open UART1 because its clock gates were already
enabled. A diagnostic candidate retained stage 2 with APB/system words
`0x7c7f503f` / `0x20f80ffe` and reset word 0. The pinned P4 register definitions
show these UART1 gate defaults as enabled. Clock enable alone did not establish
another client.

The fixture now statically reserves UART1 and rejects configured FIFO memory,
enabled UART interrupts/RS485 mode, non-idle TX or nonempty RX before adopting
that otherwise inactive boot state. It does not claim a general runtime UART
allocator. The initial failed candidates performed no UART transaction and
were restored separately. Their [raw failure logs](evidence/2026-10-28-native-rs485/failures/attempt-02.log)
and distinct identities are retained in the receipt.

Source review also corrected a guessed constant-high matrix route (P4 uses
`GPIO_MATRIX_CONST_ONE_INPUT`, 0x3f rather than 0x3c). Freestanding compilation
required `stddef.h` before the SDK header's offset assertions and the USB_WRAP
alias referenced by the generic GPIO mux helper. Those build failures occurred
before device writes. The code does not call the vendor's unbounded UART
register-update helper; update and shutdown waits are explicitly bounded.

## Exact identity and restoration

The attached ESP32-P4 revision 1.3 and device identity were rediscovered under
one exclusive serial descriptor for preflight, app installation, capture and
restoration. The actual loader matched the retained
`nihos-card-read-physical/build/card-read-main-64c67d6-frozen-01/loader` bytes.
Each candidate was audited against that loader's ELF/configuration. Only the
factory app partition at 0x10000 was replaced. The current first 64 KiB and full
1 MiB app partition were privately backed up before every trial.

Application bytes were verified before and after capture. The original full
app partition was then restored and verified, and the first 64 KiB was compared
unchanged. The final device contains the prior card image, app-partition SHA256
`41cace2fa1130c1820ff21036b628ed1689af836bd59462e914eba0c7857f0ca`,
not the UART fixture. Loader, partition table, C6 and SD were not written.

[The JSON receipt](2026-10-28-native-rs485.json) binds source archives,
image/ELF/log hashes and separate failed attempts. Public evidence includes
[input loopback](evidence/2026-10-28-native-rs485/loopback/serial.log),
[timeout control](evidence/2026-10-28-native-rs485/no-loopback/serial.log),
audits, native options, checker reports and before/after/restoration verification
logs. Private Flash backups are excluded. The captured source archives describe
the exact build inputs; subsequent documentation/evidence additions do not
change the tested firmware bytes.

## Automated validation and next wire gate

Zig Debug/ReleaseSafe suites and 218 Python regressions passed. New fault models
cover FIFO-empty while shift-register busy, bounded progress, wrong/extra reply,
local echo versus a distinct peer response, clock/timeout/UART faults and
independent cleanup failures. Invalid feature/profile selections fail before
native compilation. The evidence checker binds image/mode/capture/restoration
identity and rejects mixed boots, diagnostic faults, incomplete TX/RX, missing
shift-idle or cleanup and a positive result substituted for the timeout control.

Formatting, ZLint, ShellCheck and all six existing native ELF audits passed.
Default connected and all three UART fixture configurations passed device
image audits. The correct shim compiles; overriding its alias to UART0 at
0x500ca000 fails the intended SDK static assertion. CI builds and retains
`loopback`, `no-loopback` and `peer` profiles. Build/host evidence is separate
from the physical records above.

The external peer mode is built with:

```sh
NIHOS_NATIVE_RS485=1 NIHOS_NATIVE_RS485_TEST=peer sh tools/build-native.sh device
python3 tools/rs485-peer.py /dev/cu.usbserial-PEER build/rs485-peer.json
```

The responder runs on a **separate RS485 adapter**. The Tab5 schematic identifies
J7 pin 1 as GND, pin 3 as A and pin 4 as B; adapter polarity must follow its own
datasheet. J7 pin 2 is VIN, and pins 5/6 are I2C, outside this serial test.
The retained-loader exclusive install/capture/restore procedure still applies.
A peer pass requires the actual Tab5 TX request to be received by the adapter,
then a different opcode/payload/CRC response to be received by Tab5. A local
echo cannot pass the device's exact-response comparison. The peer script's
request/reply receipt must be retained with the identity-matched device capture;
a device-only peer record is not full wire qualification.

No separate RS485 peer has been identified or used in this checkpoint. External
DIR timing, transceiver drive/receive, termination/bias/cable conditions,
reopen/streaming/application service, optional DMA and cold power-on remain open.
