# カード表示をベース管理の空きSRAMへ移行

実装コミット: `90ba60d`。ベースは `941fbe2`。ホストとビルドの検証であり、実機への書込み・カード操作は行っていない。

カード専用の `.keypad.low` / `.keypad.high` 全域予約を除去した。ベースのリンカが公開する `__service_sram{0,1}_{start,end}` を、CPU0の共通サービス用割当が管理する。カード表示は `memory.dma` から64B境界の世代付きleaseを取得し、取得範囲内で記述子・画素・通知2バンクを構成する。描画・消去・画素再生検査にカード固有の絶対SRAMアドレスは残していない。

## 所有権と容量

- ベースの160KiB primary、56KiB stack、最低48KiB primary heap条件を維持する。loader/cacheとtop guardを含め、空き範囲が実際の割当済みsectionやloaderと重ならないことを検査する。
- 現行deviceベースの空き範囲は `0x4ff40000..0x4ff60000` と `0x4ff6e000..0x4ff9f000`。emulator/rev3ではprimaryの終端に従って最初の範囲が狭くなる。アプリがこれらのアドレスを指定することはない。
- 表示サービスは2つの連続領域を要求する。予算上限は128KiBと188KiBで、取得量は空き状況に応じて小さくなる。割当状態は内部SRAMの固定・有限metadataで管理し、CPU0の短い割当操作だけIRQをマスクする。SMP共有heapやタスク隔離の保証ではない。
- 画面を表示している間はleaseを保持する。カード除去後も公開待機画面のDMAが参照している領域は返さない。表示停止時はDMA参照終了→取得領域だけを消去→cache処理→返却の順。DMA停止や消去が失敗したら、参照され得る領域を再利用しない。
- 候補画面は引き続きCPU所有PSRAMで準備する。正確な画素配置をdry runし、容量不足ならDMAの引退や表示中SRAMの消去より前に拒否する。表示層は旧画面を維持するが、カードアプリが機密情報の終了処理を必要とする場合は従来のfail-dark方針に従う。
- 固定予約を除去したことは、表示中のSRAM使用量がゼロになることを意味しない。表示中は最大316KiBを借りる。イメージ検査はベースの予約量と貸出可能範囲を分け、実機log検査は `NIHOS_NATIVE_DISPLAY_MEMORY` の実際の取得範囲を照合する。

## 検証

Python回帰テスト235件、Zig Debug / ReleaseSafe、ZLint / fmt / shellcheckと既存の6構成のRV32 ELF検査に合格した。

追加したホスト試験は、実際の割当・容量検査コードを使う。フォント予約を除外した空き範囲、他ownerによる使用、10,000回の断片化・返却、世代の古いlease・owner違い・範囲違いの拒否、OOMの非破壊性を確認する。移動した領域での容量判定、画素の再利用、DMA所有中の領域変更拒否も確認する。既存の通知バンクと画素再生試験も固定アドレスから移動させた。

以下はRV32 deviceビルド、esptool画像生成、ELF/画像バイト・source witness・実際のloader/configとの境界検査に合格した値。primary heapの下限は49,152Bのまま。

| 構成 | DISPLAY | primary heap |
| --- | ---: | ---: |
| PIN表示デモ | 8 | 59,840B |
| 従来読取 | 9 | 50,048B |
| 写真付き読取 | 10 | 49,536B |
| カードなし画面遷移試験 | 11 / probe + exercise | 56,192B |
| 自動検知・読取 | 11 | 50,560B |

画像ハッシュ・空き範囲・検査条件は [JSON](2026-10-28-card-base-sram.json) に記録した。生のビルド・検査出力と画像は作業worktreeの `build/qualify-*` に保持している。

前景の割当・容量検査とZig側の取得・返却コードは、カード版では既存のFlash前景コード領域へ置く。これにより旧写真読取版でも48KiB heap下限を保ち、リンカ領域や下限を拡張する必要はなかった。IRQのDMA再開経路へこれらの処理を追加していない。

## 残る確認

今回は新候補をTab5へ書き込んでいない。以前の実機での点滅・行ずれ解消結果は、この変更後の実機証拠には流用しない。次はカード通信のない画面遷移試験で、新しい取得範囲、DMA画素一致、点滅・行ずれ、終了時の返却を確認する。

FreeType/HarfBuzz実験ブランチとの結合も未検証。ベースのフォント予約に合わせて空き範囲を更新した結合イメージを作り、再度境界・容量・heapを検査する必要がある。ホストの予約除外試験だけで、全券面・写真がその空き容量に収まるとは扱わない。新しい縦組みスプラッシュと画面デザインも、まだファームウェアには反映していない。
