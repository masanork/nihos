# SSH foreground PSRAM stack prototype

This is an experimental, synchronous CPU0 stack switch, not a worker task or a device SSH implementation. It depends on the 2 MiB sqld reservation and on PR #180. The foreground remains disabled at compile time until a real, qualified entropy provider is integrated.

The SSH control object occupies `0x483f0000..0x483f1000`; its exclusive 60 KiB stack occupies `0x483f1000..0x48400000`, disjoint from the owner, terminal and Scheme stacks. Existing PSRAM admission requires at least 8 MiB. CPU0 acquires the common foreground stack guard with interrupts masked, publishes the scheduler bounds, calls through a RISC-V stack-switch bridge with the previous interrupt state, then restores the original scheduler image before clearing the guard. The wrapper checks the guard and clears the borrowed stack after use. It skips the switch entirely when no SSH visit is active or visible. Bounds, alignment and nested admission are host-tested. No calls are made from an ISR.

With the unavailable entropy provider, normal and xy-trace experimental TCP device images compile and pass the standard audit; the bridge is not executed. A separate **never-executed**, disposable link study replaced the unavailable provider with zero bytes and broadly put SSH and crypto functions into Flash solely to retain the code. The 49,152 B heap assertion remained enabled; heap was 49,216 B. The standard audit rejected unapproved Flash functions. ELF `92847915ba16162f748589d6a747867a6635bb57c71e7fa2e27d1696d5075479` showed the bridge moving `sp` before calling `nih_ssh_foreground_on_stack`, and moving it back with MIE clear on return. It was not booted or flashed, and the test image was deleted. This is not a proof of interrupts, peak stack usage, cleanup, UI latency, real entropy, SSH interoperability or device behavior.

A headless ESP-EMU 0.50.0 fixture exercised this bridge with 8 MiB PSRAM, a non-secret callback and no SSH. It verified the live SP in the reserved stack, a timer tick while switched, rejection of nested foreground admission, subsequent re-admission, and zeroing of the transient stack after return. The fixture uses its own test-only patch and bypasses the product's disabled entropy gate without invoking SSH; the normal code remains disabled. The fixed fixture patch, runner, [log and image hashes](evidence/2026-11-05-ssh-stack-bridge/summary.json) make the observation reproducible via `NIHOS_EMU=/path/to/esp-emu sh probes/ssh-stack/run-emulator.sh`. This is not a real SSH session, hardware timing or physical device result.

Before enabling this path: extend the emulator test to actual SSH and failure/cancellation paths; establish call-graph and Flash/cache-off safety and meaningful SRAM headroom; measure stack high-water mark and UI response; integrate the qualified P4 entropy owner and real network; then test the exact candidate on a Tab5. Clearing the full 60 KiB stack on each active poll is intentionally conservative for transient secrets, but its cost remains unmeasured.

## Retain ownership during clearing

The foreground reservation previously ended before the PSRAM wipe. The SSH wrapper now restores the original scheduler image and checks its guard with interrupts masked, reenables interrupts, clears the transient stack, and only then releases foreground admission. Holding that admission prevents another foreground user from acquiring a partially cleared stack. It does not make unrelated memory writes impossible or demonstrate physical zeroization.

At source `f6a372466424abac85885705aea55e8cb4083f89`, headless P4 ESP-EMU with 8 MiB PSRAM passed both the non-secret stack fixture and fixed-key Ed25519 authentication fixture, including a real admission attempt after the wipe but before release. Both show rejection while held and successful re-admission afterward. `probes/ssh-stack/run-wipe-negative.sh` deliberately releases the test stack before wiping and verifies that the same admission check triggers the native task-failure marker instead of the success marker. Summaries and hashes are under `evidence/2026-11-06-ssh-stack-wipe/`. The SSH-disabled normal device image passed its audit with 54,976 bytes of heap at that source. These are emulator and image checks, not physical or network qualification; wipe duration and responsiveness remain unmeasured on Tab5.
