# Native display + touch feedback checkpoint

2026-10-27 JST。ソースは `817702a`。Tab5 / ESP32-P4 rev1.3、ST7121。
ユーザーが「ちゃんと色が出るね」と可視の色表示を確認した。
PIN入力とカード通信は無効。画面の四象限の接触座標から、SRAMの背景色を変更した。

## 実機の結果

| 観測 | 値 |
| --- | --- |
| タッチ情報 | 720×1280、最大10点 |
| サンプル数 | 2,190 |
| 接触ありのサンプル数 | 15 |
| 観測した最大接触数 | 1 |
| 象限のビットマスク | 0x0f（4象限すべて） |
| 明示的な離指 | 4回 |
| 推定した離指 | 0回 |
| 背景色の更新 | 初期化を含む9回 |
| 表示更新のチェックポイント | 3,134フレーム |
| I2C / 背景更新 / 表示の報告エラー | 0 |
| USB-A給電制御のOFF読返し | 成功 |

接触イベントは順に `(650,97)`→緑、`(646,1129)`→黄、
`(89,1195)`→青、`(42,68)`→赤。それぞれの後で、タッチICから
接触数0の明示的な報告を受け、暗い背景への更新を要求した。
今回の4回の離指は、座標なし応答からの推定を使っていない。

自動検査は、四象限とRGB565色、イベント数と集計値、離指、
表示32フレーム以上、ディスクリプタの所有領域を照合した。
従来のネイティブ300ラウンド、タスク終了、IPI/idle、メモリの検査も通った。
ユーザーの可視確認はこれらのソフトウェア上の検査とは別の証拠として保持した。

## 残る範囲

この試験の表示は小さなSRAMロゴと背景色で、全画面PINテンキーではない。
複数指、長時間の表示、ストレージ同時動作も未確認。
次は、この実機で確認した接触と明示的な離指をPIN画面へ結合する。
PIN画面を可視確認してから認証付き読取へ進む。
