# SC202CS mode preparation on the current integration base (2026-10-30)

On base `d824feaa8acc66dc16810fc9fa95887f5efc642d` plus the uncommitted camera integration worktree, the default-off `NIHOS_NATIVE_CAMERA_ID=1` fixture accepts one explicit `:camera-mode` request. The CPU0 shared-I2C owner powers on the sensor, verifies its identity, observes reset settling, writes the pinned 1280×720 RAW8 register sequence incrementally, reads back stream-off and width/height registers, then powers off and verifies expander state. It never requests stream-on or CSI/DMA. The pinned Espressif sequence, license and generator are retained; the generator check passes.

One physical Tab5 ESP32-P4 rev 1.3 trial, MAC `e8:f6:0a:e2:e8:9c`; app SHA-256 `0afdd99a836126df88e756ab2affcc286fcce6b3853013adafbc32bc26104684`, ELF SHA-256 `f1bf0dc3bd4266f86bf9afd849fbe96b3a3292fc16a24042632e65e625c12b66`. [Receipt and image audit](evidence/2026-10-30-camera-mode-main/). After two idle reports, request kind 7 was accepted and two repeated terminal reports showed state 5/result 6: configured, geometry and stream-off read back, and expander OFF readback. The launcher was ready and display frames and both CPU tick counters advanced across the request. These are repeated reports of one trial, not two independent tests.

This verifies selected register readbacks, not every setting, sensor optical output, actual power-rail voltage, touch/audio coexistence or a cold cycle. CSI, DMA, image capture, safe frame retirement and camera-to-launcher preview remain unintegrated on this base. Host tests cover sensor power, mode sequence, reset delay, readback errors, failed cleanup and exact command parsing. The original loader and app erase spans (24,576 and 147,456 bytes) were restored and verified by full readback, followed by a hard reset; restored-system boot was not captured. Raw serial data remain private; the earlier worktree's transaction and qualification helper was used.
