# C6 time image: ESP-IDF 5.5.6 build-only candidate

The running device was not changed for this experiment. The C6 time overlay
and its Network Split configuration were staged from the pinned ESP-Hosted
2.13.1 commit `0e8d0e3f0c2723deaf15441200cb4d8c53fea230` into a disposable
checkout, then built using ESP-IDF v5.5.6 commit
`880a203ae603d08a94d06aa01e0d6761958e5e9e`. The IDF 5.5.6 release notes
include Wi-Fi supplicant security fixes; applicability to this specific
configuration and all intervening advisories have not been individually
assessed. This build alone is not a security or device qualification.

The generated candidate `network_adapter.bin` was 1,308,880 bytes, SHA-256
`59170e8bb4f231ee62b0c299bf12a6db1788e8d1b2929fbb58051715e6d0ae9f`; the
1,572,864-byte OTA app slot leaves 263,984 bytes. This is 30,832 bytes larger
than the earlier 5.5.2 candidate. `esptool image_info` accepted its checksum
and validation hash. The generated 3 KiB partition table had SHA-256
`0241fa0d2e573dee86756e39fb4181e61ff7218087619cab565b602df55954d6`,
matching the prior candidate's table, not a device partition readback. The
relevant configuration retained Network Split, SNTP and the time service;
HTTPS and bootloader app rollback remained disabled in the build config. The
existing C6 bootloader's actual configuration remains unknown.

The inputs are staged with `ports/esp-hosted-c6-time/reproduction/apply.py`.
The resulting 5.5.6 configuration is recorded as
`ports/esp-hosted-c6-time/reproduction/sdkconfig.idf556`, SHA-256
`f50c1fc3e6b04b0dfcce5349fb18095b67cd4642e692927af8caff14e353ab7d`.
The dependency lock template uses `@IDF_PATH@` as a placeholder: substitute
the absolute 5.5.6 root before using it as `slave/dependencies.lock`. An initial
build silently resolved the local `cmd_system` dependency from 5.5.2 because
the copied lock held an absolute old path. That build is not the evidence
above. After correcting the lock, reconfiguration reported `cmd_system` from
the 5.5.6 root and IDF version 5.5.6; the managed registry dependencies remained
at the recorded versions. The compiler was `esp-14.2.0_20260121` and the
component-manager parent-PID fallback was used as in the original experiment.

The upstream `Kconfig.projbuild` references `$(ESP_IDF_VERSION)` and the build
required exporting `ESP_IDF_VERSION='"5.5.6"'`. The environment did not define
`ESP_ROM_ELF_DIR`, so optional GDB helper generation emitted a warning even
though the application build and image checks succeeded. The build also
reported unrelated Kconfig warnings about disabled ESP32 BT UART fields.
Checkout paths can affect generated protobuf contents; the binary hash is an
identity for this build, not a promise of path-independent reproducibility.
Artifacts remain under `/private/tmp/nihos-c6-idf556-build/`; do not flash the
candidate solely on the basis of this record. C6 OTA, handshake, NTP/RTC,
Wi-Fi/BLE, rollback, and independent recovery remain to be tested.
