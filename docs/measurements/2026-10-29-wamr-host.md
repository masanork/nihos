# WAMR host interpreter experiment

Date: 2026-10-29. This is a host-only feasibility experiment in the uncommitted
SDK worktree based on `c0ff17d5ea6802eed4769a5b588da1735dbfbd32`.

## Reproduce and provenance

Run `sh probes/wamr-host/run.sh` on an AArch64 or x86-64 host with Rust,
Node, CMake and C tools. The script obtains WAMR 2.4.5 from
[upstream](https://github.com/bytecodealliance/wasm-micro-runtime), checks the
exact commit `25bd7eb63e828e4bd242cc9b38d260b4b31c6605` and rejects modified
source. The checkout lives under ignored `build/`; it is not vendored. WAMR is
Apache-2.0 with LLVM exception; see its upstream `LICENSE`. This experiment is
not a decision to import or redistribute its code.

Configuration: Apple silicon macOS AArch64, Rust 1.98.1, Node 26.12.1;
WAMR classic interpreter, instruction metering enabled, hardware boundary
checks disabled, JIT/AOT and built-in libc/WASI disabled. Runtime pool is
4,194,304 bytes. Bounds checks are not disabled. The generated Wasm fixture
is 903 bytes, SHA-256
`6bcdade03fd4d1c942208568e985e46deb9232a66a5b8228867fbeb150803be0`.

## Observed

The same Rust source as the native probe was loaded into WAMR, and both input
states produced the expected drawing calls. The host registered explicit
`nihos` imports and validated pointer and length against the module's linear
memory before reading, with the same current printable-ASCII policy as the
native fixture. Tests cover native error propagation, invalid state, a real
Wasm import with overflowing address, unsupported bytes, a deliberately
infinite Wasm loop stopped at 10,000 instructions, a too-small runtime pool,
and a truncated module. Test assertions remain enabled in the Release build.
The test host has bounded synchronous imports; it is not production code.

WAMR reported linear memory range of 1,114,112 bytes and a pool usable size of
4,193,888 bytes with 21,792 bytes high-water usage during this run. The pool
measurement is *not total runtime memory*: this host configuration obtains
linear memory through the platform mapping path; the linear range is a logical
accessible size, not measured resident bytes. Module input, C stack, runtime
code, OS mappings and other process memory are also outside this pool figure.
The 4 MiB pool is a test reservation, not a device requirement or a per-app
limit. No device memory or performance is inferred.

## Remaining

No nihos WAMR port, RV32 link, emulator execution, real service integration,
physical execution, application isolation or resource policy was established.
Instruction metering does not bound time spent in host calls; actual allocation
and memory growth limits, process separation, trap/cleanup semantics, queued
input, and per-app ownership need separate contracts and adversarial tests.
The selected Rust target's 17-page initial memory should be tuned and tested,
not silently assumed acceptable. Compare any port against other runtimes only
under the same workloads, build options, memory accounting and hardware.
