# Native count-only keypad checkpoint

2026-10-27 JST。Tab5 / ESP32-P4 rev1.3、ST7121。
ソース `8beab48` の全画面テンキーを実機へ書き込み、表示開始とIRQ更新を確認した。
数字そのものを保存せず、0〜4の入力数だけを扱う操作確認デモである。
USB/JPKI/CARD_CHECKはビルド時に拒否し、USB-A給電制御のOFF読返しも確認する。
カードへのPIN送信はない。

## 表示方式

最初の `66ddafc` は、可変画素をPSRAMから読む方式で表示開始時にFIFO underrunとなった。
`stage=4 / error=7 / bridge_error=1 / frames=0` を保存し、バックライトを消して停止した。
カード処理には進んでいない。この試行を成功記録で上書きしていない。

`8beab48` は固定の文字画素203,144 bytesをFlashから起動時にSRAMへコピーする。
表示中は固定色・文字画素・入力数の小さなテクスチャすべてをSRAMから読む。
637個・40,768 bytesのDMAディスクリプタもSRAM上に置く。
変更するのは丸印と確認ボタンの小さな二重バッファで、フレーム境界で参照先を切り替える。

専用領域は `0x4ff40000–0x4ff60000` と `0x4ff70000–0x4ff9f000`。
SDKのメモリ配置に照らして、既存の56 KiBスタック領域、ROM予約、L2キャッシュと分離した。
領域は書込可・実行不可のNOBITS、Flashの画面データは読取専用・実行不可で監査する。
既存内部ヒープは60,544 bytesで、48 KiB下限は変更していない。

## 今回の実機チェックポイント

約120秒、5,702サンプル、7,874表示フレームで報告エラーは0だった。
入力数0の描画は継続したが、キー操作イベントは0件である。
そのため操作試験の厳格な検査は不合格となり、成功マーカーは作成していない。
表示開始・IRQ・メモリだけを検査する独立チェッカーは合格した。
書き込み、事前Flash照合、キャプチャ、事後Flash照合まで排他的シリアル接続を維持し、
事後照合も3領域すべて一致した。最終照合に伴う再起動後も同じデモを本体に残した。
実機の可視確認と操作結果はユーザーの確認待ちである。
