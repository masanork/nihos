# カードサービス：入力補助APまでの最初の実装

実装順は、(1) 共通サービスと本体PIN入力、(2) 券面事項入力補助、
(3) 利用者証明用のチャレンジ署名と検証、(4) 署名用・券面APとする。
この変更は **(1)(2) の独立した処理部分と、PINなしのネイティブ接続確認**。
表示側の確定コミット `10a4cb6` を取り込んだ。ネイティブでの
フレームバッファ文字表示は未確認であり、PIN入力画面と認証読取は未結合である。
既存の `NIHOS_NATIVE_JPKI=1` は引き続きPINなしの起動時診断であり、
このサービスやPIN入力を有効化するフラグではない。

## 実装済みの範囲

- `src/card/service.zig`: 一所有者、固定バッファ、同時に一要求だけを
  発行する状態機械。生のAPDU送信APIは公開しない。
- `src/card/pin_entry.zig`: 本体用テンキーのヒット領域と入力モデル。
  表示用Viewには入力桁数だけを渡す。座標は縦720×1280。
  長押しで連打せず、指を離したときに一度だけ確定する。
  複数接触・キー外への移動・画面切替で押下を取り消す。
  実際の描画、フォント、タッチ入力モデルとの結合は残っている。
- `src/card/ccid_owner.zig`: サービスが生成した要求だけをCCIDへ渡す。
  スロット、シーケンス、状態、長さ、連結指定を検査する。
  time extensionは最大4回の受信で処理し、OUTを再送しない。
- `src/card/input_support.zig`: 入力補助APのEF0002を最大2 KiB、
  256バイト単位で読み、DF22〜DF25の氏名・住所・生年月日・性別を解析する。
  切れたTLV、重複、必須項目欠落、不正UTF-8を失敗にする。
  日付・性別の文字列はカードの値を保ち、未確認の形式変換をしない。
- `src/board/tab5/touch.zig`: ST7121/ST7123、GT911の有界I2C読取。
  新しい報告がない場合は指を離したことにせず、リセット・不正座標は失敗にする。
- `src/platform/native/usb_probe.zig` のDevice: 起動プローブとは別の所有リンク。
  CHENAの停止確認、停止不能時のPHYリセット、DMAコピーの消去を行う。
  この接続確認用リンクはPIN付きVERIFYを拒否する。
  キャッシュ消去や停止に失敗した場合もカード要求の成功として公開しない。

APDUの識別子と読み順、TLVタグは、ユーザー指定のciv
`54a843e656513930df60bbc20d752ff3289e7078` の
`src/jpki.rs` と `crates/civ-card/src/{apdu,jpki_utils}.rs` を参照した。
Rustライブラリやその実行環境は組み込んでいない。

## PINと失敗時の扱い

1. 電源投入、入力補助AP/PIN EF選択、データなしVERIFYで残り回数を読む。
2. 残り2回または3回のときだけ入力を受け付ける。0回・1回、
   回数不明、既認証を示す9000ではPINを送らず終了する。
3. 本体の明示的な送信操作後に、データなしVERIFYで回数を再確認する。
   入力待ち前と異なる場合、最後の1回になった場合、通信異常時は
   保留PINを消去し、PINを送らない。
4. PIN付きVERIFYは一度だけ発行する。誤PINなら残り回数を記録して終了する。
   応答を失った場合は結果不明にし、古い残り回数を表示しない。
   新しい認証操作には結果の明示的な破棄と新規開始が必要になる。
5. PINの入力領域・保留領域・送信領域は使用後にsecureZeroで消去する。
   キャンセル時、発行済みDMAが借用しているコマンドは転送終了まで保持する。
   すでに発行したVERIFYをキャンセルで撤回できるとは扱わない。
6. 読取成功でもカード電源OFF完了まで結果を公開しない。
   キャンセル、失敗、結果破棄で属性バッファも消去する。

サービス自身にはシリアル入力、ログ出力、保存、PIN変更・解除、
マイナンバーEF読取、署名処理はない。テストのPINと属性は架空値のみ。
ここで得られる四属性は **読取・構文解析結果** であり、発行者署名や
証明書チェーンによる真正性確認済みとは表示しない。

## ネイティブ側に結合するときの契約

`Service` / `Entry` / `Owner` は同じカード所有者だけが変更する。
別タスクから直接共有して変更せず、タッチ座標や開始・キャンセル要求を
所有者へ送り、画面向けの状態を公開する。PINを汎用ログや永続キューに流さない。
属性Viewのスライスはサービス内部を借用するため、結果破棄後には使えない。

`Owner.step` は同期呼出しなのでUIタスクや割込みから呼ばない。
Linkの `send` / `receive` は時間上限を持ち、成功・失敗を問わず、
渡された領域へのDMAアクセスを終了してから戻る。
`scrub` はDMAを停止し、Link内部のDMAバッファに残るコピーも消去して戻る。
停止を保証できない場合、バッファを再利用せず、コントローラをリセットする。
既存USB起動プローブのSessionはPINを拒否するため、そのままLinkには使わない。

LinkはCCID単位で応答を組み立て、USB短パケットを含めて最大512バイトを
検査可能な形で返す。エラー後の遅延応答を次の要求へ流さず、
必要ならUSBを再初期化する。カード/リーダーの取り外しを監視し、
所有者が転送を停止した後 `disconnected()` で入力待ちを失効させる。
画面離脱、待機期限切れ、アプリ終了でも入力を消去してキャンセルする。
古い要求番号の完了通知や古い入力画面からの送信は拒否する。

## 検証と残りの作業

PINなしの実機接続確認用イメージは次で作る。

```sh
NIHOS_NATIVE_USB=1 NIHOS_NATIVE_DISPLAY=1 NIHOS_NATIVE_CARD_CHECK=1 \
  sh tools/build-native.sh device integer
```

CPU0/CPU1の既存検証が終わってから、CPU0がタイマ・I2C・USBを専有する。
入力補助APの残り回数をデータなしVERIFYで読み、PINを入力せずカード電源を切る。
その後タッチを64回読む。スキャンアウトとの同時動作はこのモードでは許可しない。
`NIHOS_NATIVE_CARD_CHECK` は残り回数、電源OFF、DMA消去、タッチの
新規報告・離指・接触報告数を出力し、PINや属性値、座標は出力しない。
接触報告が0ならI2C読取だけの証拠であり、指操作の確認にはならない。
`capture-native-usb.py --card` は、この完了報告まで待ち、厳密な検査器に渡す。

```sh
.tools/zig-0.17.0/zig build test
.tools/zig-0.17.0/zig build test -Doptimize=ReleaseSafe
sh tools/check-card-rv32.sh
sh tools/run-static-analysis.sh
```

ホストでは正常系、各段階の通信失敗、誤PIN、結果不明、残り1回、
入力中の回数変化、遅延完了、キャンセル、読取上限、CCID応答不正、
time extension、タッチ入力の保持・移動・複数接触を検証する。
`check-card-rv32.sh` はサービス・入力・CCID処理の全入口を
RV32IMACのオブジェクトへコンパイルする。Linkの外部関数は未解決で、
起動可能なアプリへのリンクやターゲット実行の証拠ではない。

次の結合段階では、表示の可視性を確認し、描画・タッチ・画面離脱処理と
常駐カード所有者を結んでから、本体だけでPINを入力する。
PINのない操作確認を先に行い、正しいPINを一度だけ入力してEF0002読取、
電源OFF、画面終了時の消去を実機で確認する。誤PINを実カードで試して
テストする必要はない。現時点ではこの変更による実カードへのPIN送信はない。
